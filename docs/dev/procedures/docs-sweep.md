# The docs sweep

What a docs sweep checks and how it reports. Read when the owner says yes to one. When it is offered is in `AGENTS.md`.

## The checks, in order

1. The roadmap and open questions against what was done, and each **Built by** (one naming a finished phase or part is
   stale).
2. Decisions from the session missing from their file.
3. New terms.
4. Anything in the wrong file by "Where things go" in `AGENTS.md`, `AGENTS.md` itself included: the steps of a job, a
   mode or a routine belong in `procedures/`.
5. Sizes, by "How docs grow" in `AGENTS.md`.
6. The ideas: built ones move to decisions, dropped ones go.
7. The friction, as counts by kind with a fix for each.

## The report

Report only what needs the owner, flagging borderline calls (decision or still open, idea or problem) instead of
guessing; what changed is in the commit message, and what was checked and found fine is left out. The same goes for any
report on docs.
