# Corrections: a running entry

How an entry that is still running is put right. Each decision follows the template in `../README.md`, and is cited by
its title.

## A running entry is edited at its start (2026-11-25)

**Decision:** a running entry heads both lists ("The main screen has a controls side and a dashboard") and opens in the
edit popup as any row does, but only its start and its profile can change. Its end is now, read once as the edit opens:
the now-line on the line, holding still while the edit is open, with no handle and no time label of its own, and the
result under the day shows its start alone. It cannot be divided, and it has no "Ta bort": it is stopped first. Its
start docks onto an earlier entry of its profile as any handle does, and the joined entry runs on ("Two entries join by
docking"), and a profile picked that its start's neighbour has takes that neighbour in; a join with it comes only from
its own edit. No other entry touches a running entry of its own profile: a handle dragged or stepped toward it, and a
forgotten entry placed before it, stop at the last 5-minute mark before its start, so 07:00 with it running since 07:03
and 06:55 with it running since 07:00; an entry already ending closer keeps its end. In another entry's edit, a profile
that would make it touch a running entry of that profile is greyed in the picker, its name followed by "· pågår"
("Utveckling · pågår"), so the running entry is edited instead. Entries of other profiles touch it freely, as a switch
on the fly leaves them. Its break is set through its tag, as on any entry. A change needs a reason, as any edit; a
reason alone may be saved, as on any entry ("Every edit carries a reason"). Saved, it runs on from its new start, on its
new profile, marked edited if a time or its profile changed.

**Why:** a forgotten start is the commonest fix, and it is noticed while working; without this, the fix was to stop,
correct and start again, which split the entry in two and needed a join. A wrong profile, seen while it runs, is fixed
the same way. Keeping the end at now leaves nothing about a running entry that the clock has not yet settled.

**Rejected:** a running entry not editable at all, out of the lists until stopped: the commonest fix would take a stop,
a correction, a new start and a join. Its end editable too: it is now, and still moving. An earlier entry docking onto
it: the joined entry ran on, its end handle gone, the end it was opened to change. A switch onto its profile allowed and
taken in: the same join through the picker. A gap of its own length kept before it: the 5-minute marks already give one,
with no new number.
